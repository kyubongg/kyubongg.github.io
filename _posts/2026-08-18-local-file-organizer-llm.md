## 왜 만들게 됐나

내 데스크탑은 항상 파일이 난잡하게 흩어져 있다. 다운로드한 문서, 캡처 이미지, 작업하다 만 스크립트들이 뒤섞여 있고, 정작 필요한 파일을 찾으려면 한참을 뒤져야 한다. 문제는 폴더 정리 자체를 내가 잘 못한다는 것이다. 분류 기준을 세우는 것도, 그 기준을 꾸준히 지키는 것도 나에게는 잘 안 맞았다.

그래서 이 반복적이고 판단이 필요한 작업을 LLM에게 위임해보기로 했다. 파일을 스캔하고, 내용을 이해하고, 알맞은 폴더로 분류해서 옮겨주는 시스템을 로컬 환경에서 직접 만들어보는 프로젝트다.

## 전체적인 흐름

현재 구상하고 있는 파이프라인은 다음과 같다.

1. **파일 이름 스캔** — 대상 디렉토리를 훑으며 파일 목록과 메타데이터를 수집한다.
2. **파일 내용 분석** — 파일을 열어 내용을 파악한다. 지금 단계에서는 텍스트 기반 파일만 분석이 가능하고, 이미지나 바이너리 파일의 내용 분석은 아직 지원하지 못한다.
3. **LLM의 폴더 분류 제안** — 스캔한 이름과 분석한 내용을 바탕으로 LLM이 어떤 폴더로 옮길지 제안한다.
4. **실제 이동/정리 실행** — 제안된 분류에 따라 파일을 실제로 이동시킨다.

아직 3번과 4번 사이에 사용자 확인 단계를 둘지, 아니면 신뢰도가 높을 때만 자동 실행할지는 고민 중이다.

## 기술 스택

기술 스택은 아직 완전히 확정되지는 않았지만, 지금 잡고 있는 방향은 이렇다.

- **언어**: Python. 사실 익숙한 언어는 아니지만, LLM/로컬 모델 관련 생태계(Ollama 연동, 파일 처리 라이브러리 등)가 가장 풍부해서 선택했다.
- **LLM**: [Ollama](https://ollama.com) 환경에서 `qwen3.5:4b` 모델을 사용 중이다.
- **왜 로컬 LLM인가**: 단순히 API를 호출하는 대신 로컬 환경에서 직접 모델을 튜닝해보고 싶었던 것도 이 프로젝트를 시작한 이유 중 하나다. 내 파일이 외부로 나가지 않는다는 점도 데스크탑 정리라는 용도에는 잘 맞는다.

## 지금까지의 한계

- 파일 내용 분석이 텍스트 기반 파일로만 한정되어 있어서, 이미지·PDF·압축 파일 등은 파일명 정보만으로 분류해야 한다.
- 4b 크기의 로컬 모델이 분류 판단을 얼마나 안정적으로 해줄지는 아직 검증 전이다.
